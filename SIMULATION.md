# MentorPi navigation in Isaac Lab

Goal-reaching and obstacle avoidance for the **MentorPi M1 with depth camera**. The task is an Isaac Lab `DirectRLEnv`, with RSL-RL PPO training. Each step generates a **100 × 100 binary local occupancy map** from task obstacle geometry and the robot's current pose. No LiDAR or camera rendering is used as policy input.

## Run on this computer

### Lightweight Python viewer (recommended for policy inspection)

```powershell
# Load the trained empty-room policy automatically; CPU playback, no Isaac renderer.
.\scripts\view-navigation.ps1

# Select another checkpoint. Settings are taken from its neighboring task.json.
.\scripts\view-navigation.ps1 -ViewerArgs @('--checkpoint', 'logs/grid_obstacles/final.pt')

# Use the trained task's layout/settings but drive manually.
.\scripts\view-navigation.ps1 -ViewerArgs @('--manual')

# Test an empty-room checkpoint against four obstacles while following new saves.
.\scripts\view-navigation.ps1 -ViewerArgs @('--run-dir','logs/grid_extended','--follow','--seed','123','--obstacles','4')
```

The Tkinter window shows the arena, robot heading, goal, movement trail, live 100 × 100 policy grid, commanded actions, actual velocities, distance and episode status. Use Pause, Step, New episode, Auto-reset and playback speed controls. Manual controls: W/S forward/reverse, A/D sideways, Q/E rotate. Click free arena space to change the goal for interactive debugging. Blue/green map markers are overlays, not extra model input channels.

`--obstacles N` explicitly overrides only the viewer's obstacle count (0–8 for current checkpoints). The window displays both the evaluation count and training count. Obstacles use the existing reachable-layout sampler, are included in the policy grid and collision checks, and are regenerated by New episode. The override persists when Follow newest checkpoint or the checkpoint selector loads another snapshot. This is an interactive challenge scenario; it changes neither checkpoint files nor training settings. A policy trained in an empty arena may not avoid newly introduced obstacles. Formal Isaac Lab evaluation still requires matching the task manifest.

The **Checkpoint** selector lists snapshots in numeric iteration order. Refresh discovers new saves. **Follow newest checkpoint** automatically loads a newly written model after its size/mtime are stable across two polls, retaining the current policy while a save is incomplete. Switching models resets playback with the same `--seed`, allowing comparison on the same initial scene. Use different seeds/New episode to check generalization; this visual comparison is not a multi-episode success-rate evaluation.

## Model and policy interface

- 20 Hz control, normalized actions `[vx, vy, yaw_rate]` in `[-1, 1]`.
- Initial speed limits: `[0.2 m/s, 0.2 m/s, 0.5 rad/s]`, based on the vendor app command clamps, **not hardware maximum specifications**.
- Configurable acceleration limits; zero command brakes toward zero rather than instantly stopping.
- Robot is a conservative **0.15 m radius disc**. Imported visual bounds are about 0.212 × 0.171 × 0.143 m; the disc encloses the horizontal visual footprint. Confirm this against the actual assembled robot before deployment.
- 4 × 4 m square arena, up to eight static circular obstacles, default obstacle radius 0.22 m.
- Motion is piecewise linear with exact segment/disc collision tests. Collision attempts keep the previous safe position, zero the velocity, penalize and end the episode. No contact forces, pushing, tipping, wheel traction, or cosmetic wheel animation is implemented.
- Original robot is referenced with its `Physics=none` variant; lowest visible geometry is aligned to the floor. A heading marker makes +x visible. Only the first environment is drawn by default; all training environments have independent state.

The policy receives **two inputs**, totaling 10,008 numbers:

| Input | Shape per environment | Meaning |
| --- | --- | --- |
| `occupancy` | `1 × 100 × 100` | Binary local map: **0 = clear, 1 = occupied** |
| `policy` | `8` | Relative goal xy (2), normalized actual body velocity (3), previous normalized action (3) |

A small CNN encodes the grid; its output is combined with the eight state values to choose the three movement commands. The actor and critic both receive the grid and state; neither receives the old obstacle list or wall-distance vector.

### Occupancy map contract

- Default resolution: **0.05 m per tile**, covering **5 × 5 m**. Set `--map-resolution` to change coverage while preserving 100 × 100 cells.
- The map translates and rotates with the robot. Image top is robot-forward (+x); image left is robot-left (+y). As 100 is even, the robot origin is at the intersection of the middle four tiles, not the centre of one tile.
- Tile centres are `x = (49.5 - row) * resolution`, `y = (49.5 - column) * resolution` in the robot frame. The robot's pose maps those locations into environment coordinates.
- A tile is occupied if it intersects an active circular obstacle, crosses an arena wall, or is outside the arena. Tile/circle intersection checks avoid dropping thin obstacles between cell centres. A conservative micrometre tolerance stabilizes wall tangencies under rotation.
- Default cells represent physical occupied space, with **no footprint inflation**. Collision checks still use the robot radius. Optional `--map-inflation 0.15` produces a binary expanded blocked region; it never creates graded costs. The map contract is recorded in each checkpoint manifest.
- The robot itself is excluded. Goal and robot markers are not burned into the binary policy map; the goal is supplied separately.
- The Isaac Lab environment generates the map on every observation using the same obstacle positions and sizes that drive task collision and scene visuals. At present those objects are the task's generated cylinders and square boundary. Arbitrary USD meshes added outside this task are not automatically rasterized.
- No occlusion or unknown cells: this is a ground-truth binary occupancy map resembling a Nav2 map, not the full Nav2 multi-layer costmap implementation or an imitation-learning dataset. Nav2 costmaps can also contain unknown and graded inflated costs: [Nav2 environmental representation](https://docs.nav2.org/jazzy/getting_started/navigation_concepts/environmental_representation/).

Smoke/evaluation runs save `occupancy_binary.png` (the exact 100 × 100 binary observation, black = occupied) and `occupancy.png` (enlarged preview with robot/goal overlays). The overlays are never policy inputs.

For real deployment, supply the same robot-aligned occupancy contract from a map/localization system or camera perception. The training map currently includes ground-truth obstacles on all sides; a forward-facing depth camera alone does not provide that information. This implementation has no perception noise, missed detections, command latency, or moving obstacles.

## Episodes and learning

Reset samples obstacle positions and selects start/goal cell centres from a connected free-space component. Obstacles are inflated by robot radius, margin, and half a grid-cell diagonal. This guarantees a collision-free grid route without forcing a clear straight line between start and goal. Starts/goals are separated by at least one metre.

Reward per step: `5 * distance_progress - 0.01 - 0.01 * action_change_squared`, with `+10` for arrival and `-10` for collision. Success is within 0.15 m of the goal; timeout is 40 s. Collision overrides arrival. Isaac Lab resets terminal environments automatically; rewards/outcomes are captured before reset.

PPO uses a three-layer grid CNN plus 128 × 128 actor/critic heads, 32 rollout steps, and four mini-batches. Each training run saves a task manifest, local TensorBoard logs, periodic checkpoints, and `final.pt`. Evaluation reports completed episodes, successes, collisions, timeouts and success rate. A short run verifies training plumbing, **not a learned navigation policy**. Use held-out seeds and enough complete episodes to assess performance.

Resume/evaluation validates the checkpoint's neighboring `task.json` against the current dynamics/observation settings. **Old 44-value obstacle-list checkpoints are incompatible**. Use `--scenario-file scenarios/mixed_training.json --transfer-scenario` to transfer to expanded layouts in a new log directory; this retains weights and resets the optimizer/iteration. Footprint, dynamics, action scaling and map semantics must remain compatible.

## Generalization experiments

`RESULTS.md` records benchmark results. `mentorpi_nav/cli/evaluate.py` runs a fixed number of complete episodes using the exact shared analytic dynamics, without starting Isaac Lab or rendering. Evaluation loads the actor alone: it does not use the demonstration planner.

```powershell
$navPython = "$env:USERPROFILE\Desktop\mentorpi\IsaacLab\.venv\Scripts\python.exe"
& $navPython -m mentorpi_nav.cli.evaluate --checkpoint logs/mentorpi_navigation_best/final.pt --scenario-file scenarios/original_four.json --seeds 456 789 2026 --episodes 200 --output logs/recheck_selected
.\scripts\benchmark-scenarios.ps1 -Checkpoint logs/mentorpi_navigation_best/final.pt -Output logs/recheck_challenges
.\scripts\view-navigation.ps1 -ViewerArgs @('--run-dir','logs/mentorpi_navigation_best','--seed','789')
```

Scenario profiles include variable counts/radii (`varied`), a divider with a narrow opening (`passages`), longer start-goal distances (`long_routes`), and a combined training distribution (`mixed_training`). Original four-obstacle cases can be restored explicitly with `original_four.json`, allowing identical comparisons across architectures.

`mentorpi_nav/cli/train.py` provides training-only A* demonstrations and learner-state corrections (DAgger). `--goal-residual` creates a goal-conditioned residual CNN: a relative-goal steering prior supplies basic movement and the learned grid branch supplies corrections. Its manifest identifies this architecture and the supervised training method. These checkpoints load in the lightweight viewer and can initialize Isaac Lab PPO with `--transfer-scenario`; supervised loss alone is not a navigation success metric. The goal-steering prior assumes the current 4 m arena and 0.2 m/s translation limits.

## Validation

```powershell
& "$env:USERPROFILE\Desktop\mentorpi\IsaacLab\.venv\Scripts\python.exe" -m unittest discover -s tests -v
```

Tests cover coordinate rotation, strafing, acceleration and speed bounds, swept collisions (including tunnelling/tangency), binary map shape/values, tile placement, translation/rotation, wall inclusion, thin obstacles, invalid-object masking, optional inflation, partial reset isolation, reward direction and seeded layouts. Integration checks use the installed Isaac Lab runtime, the imported MentorPi visual, CUDA CNN/PPO and checkpoint reload.

Key files:

- `mentorpi_nav/core.py`: batched motion, observations, collision, reachable reset sampler.
- `mentorpi_nav/lab_env.py`: Isaac Lab task, scene visuals, rewards/dones/resets.
- `mentorpi_nav/agent.py`: PPO settings.
- `mentorpi_nav/cli/simulation.py`: smoke/train/evaluate entry point.
- `mentorpi_nav/playback.py`: strict checkpoint loading and simulator-free playback.
- `mentorpi_nav/cli/view.py`: lightweight Tkinter arena/map viewer.

The reset sampler uses CPU flood-fill and the initial implementation draws USD objects individually. This is appropriate for initial small experiments, not yet optimized for thousands of environments. Tune the policy, validate held-out behavior, then add perception realism and deployment support.
